# Milestone 6.6 — `nmapdb` and `lpeg`: Phase-0 analysis

This is a new kit cycle (PLAYBOOK Phases 0–1). It covers the two C modules
that every nmap build registers and that the port does not have yet:
- **`nmapdb`:** `nse_db.cc` (113 lines), over `MACLookup.cc`, `services.cc`
  and `protocols.cc`.
- **`lpeg`:** `lpeg.c` (3,694 lines, LPeg 0.12), built through `nse_lpeg.cc`
  (21 lines). Three pure-Lua libraries run on top of it unmodified:
  `nselib/re.lua`, `nselib/lpeg-utility.lua` and `nselib/json.lua`.

M6.5-ANALYSIS.md decided D0(iii) on 2026-10-09: these two modules come first,
before any `openssl` code, because `-sC` aborts at start-up without them.

This document contains:
- the inventory;
- the C-flaw scan;
- the threat model;
- a dependency-ordered plan.

**No port code is written until the decisions in §9 are approved** (kit
requirement). Step 0b's spike is scratch Rust, used only to measure.

**Where the numbers come from.** Every count was measured against one of:
- the C tree in this repository;
- the installed `/usr/bin/nmap` (Debian 7.94SVN, built from `3be01efb1`,
  system liblua 5.4.6);
- standalone oracles built in scratch:
  - this tree's `liblua/` plus `lpeg.c` (`build_lua_oracle.sh`, the M6.2
    oracle);
  - the same at `3be01efb1` and against upstream liblua 5.4.6;
  - an ASan/UBSan build;
  - 16 deliberately sabotaged `lpeg.c` builds;
  - `nse_db.cc` with the real `MACLookup.cc`, `services.cc` and
    `protocols.cc` at both revisions.

None is recalled from memory. Anything not verified is marked
**unverified**.

**How the analysis was checked.**
- **The draft** was written from five independent investigations:
  - the LPeg C surface;
  - a corpus census;
  - `nmapdb`;
  - the design on piccolo;
  - the oracle.
- **Three adversarial reviews** then attacked it (fidelity, security, and

  sabotaged LPegs, and overturned or sharpened ten of them (§8). The largest

## 1. Five findings that shape the milestone

### 1.1 LPeg's worst-case time is exponential at every stage, and nothing in the C bounds it

LPeg backtracks without memoising. Its analyses also re-walk shared
sub-grammars. Measured on the tree oracle, split by stage:

| shape | build `P(g)` | compile (first match) | match (cached) |
|---|---|---|---|
| chain `Rᵢ ← Rᵢ₋₁'x' / Rᵢ₋₁'y'`, n = 22 / 24 | 0.134 / 0.547 s | ≈3.0 / ≈13.0 s | 0.080 / 0.319 s |
| choice chain `Rᵢ ← Rᵢ₊₁ + Rᵢ₊₁`, k = 22 / 24 / 26 | 0.090 / 0.356 / 1.543 s | — / 0.915 / 3.762 s | 0.00 s |
| `S <- 'a' S 'b' / 'a' S 'c' / ''` on `a`ⁿ`d`, n = 18 / 20 / 22 / 24 | — | — | 0.008 / 0.034 / 0.135 / 0.545 s |
| `(P"a"^0*"b"+1)^0` on `a`ⁿ, n = 4,000 / 8,000 | — | — | 0.005 / 0.021 s (quadratic) |
| `((P"a"^0*"b"+1)^0*"c"+1)^0` on `a`ⁿ, n = 500 / 1,000 / 4,000 | — | — | 0.018 / 0.135 / 7.7 s (cubic) |

**Where the time goes:**
- **Build:** `verifyrule` (`lpeg.c:3047`, both `TChoice` arms at
  `:3071-3073`).
- **Compile:** `getfirst` (`:1175`, `TChoice` at `:1190-1196`) and `codegen`,
  via `prepcompile`, called lazily from `lp_match`.
- **Elsewhere:**
  - `lpeg.B` runs `fixedlenx` (`:1125`): 0.851 s at k = 26;
  - `p^n` runs `nullable`/`checkaux` (`:1084`): 0.164 s at k = 24;
  - **capture evaluation** is exponential through back-references with no
    Lua call involved: nested `Cb"a"*Cb"a"` takes 0.143 → 9.427 s for
    k = 20 → 26 (`backrefcap` `:527`, `pushnestedvalues` `:469`).

**Nothing in the C bounds it.**
- The default backtrack limit does not bound time: the exponential match at
  n = 24 recurses only 24 deep, under the ceiling (the first failure is at 50).
- A C function cannot be interrupted, so nmap's `--script-timeout` cannot
  stop any of these stages.

**The pattern matcher's memo cannot be borrowed for matching.**
`pattern-worst-case-time-is-bounded` records *failed* states, which is exact
for Lua patterns. LPeg's matching blow-up comes from re-running rule calls
that *succeed*, with captures, side effects and backtrack-stack use that
decide which inputs raise `too many pending calls/choices`. No exact memo is
known.

**The analyses are different.** `getfirst`, `headfail`, `nullable` and
`fixedlen` are pure functions of a node, plus the follow set for `getfirst`
and the call count for `fixedlen` (`lpeg.c:1137`), so an exact memo exists
for them (E10).

**Who controls what:**
- Patterns are built from script constants. Two user inputs also reach them:
  the `fingerprint-strings.n` script argument (`fingerprint-strings.nse:97`),
  and `--script`, which the port already parses in Rust.
- The network controls subjects only.
- Every corpus pattern over network data measured linear on the shapes
  tried: the drafted set, plus `anywhere("%r(")` with no match, `parse_fp`
  on unterminated quotes, and `get_response` over 100k backslashes
  (0.0005–0.0075 s at n = 100k).
- **Step 0b's adversarial search** found every network-facing corpus
  pattern linear in subject size up to 64 KiB (§9 D3).

So the exposure is a pathological pattern written by a script. That is the
threat class of `while true do end`. The port pre-empts such code, but only
code that returns to the VM. **A Rust callback that builds or compiles a
grammar runs to completion inside one VM slice, where the stall watchdog
cannot see it** (`crates/cli/src/nse.rs:9-12`). D3 therefore has to cover
every stage, not only the match loop.

### 1.2 nmap 7.94's LPeg crashes on script-built patterns, and corrupts `json.parse` on network input

**Crashes.** The ASan/UBSan screen flagged 112 cases (seed 1) and 158
(seed 2) out of about 61k each.

**Which binary crashes depends on the harness.** Through one probe H06
crashes 7.94; through another H07 does. H09 ends in SIGSEGV in one harness
and in `double free` (SIGABRT) in another. So every row below is "crashes in
at least one harness", and **no per-binary outcome is used as a pin**.

| trigger | defect |
|---|---|
| `lpeg.match(lpeg.Cc(nil), "")` | `Cconst` reads the ktable of a pattern that has none |
| `-(lpeg.S""*"a")+"c"`; `lpeg.P{lpeg.P""}^-1` | the peephole's `i--` re-scan (`lpeg.c:1846`) loses alignment and reads a jump target outside the code array; `finaltarget` (`:1508-1509`) is only where it crashes. Layout-dependent |
| `lpeg.P{"A",A=lpeg.B(lpeg.P"a"-lpeg.V"A")}` | left recursion through `B` escapes the verifier |
| `lpeg.C` nested 300 deep | pushes with no `luaL_checkstack` |
| a `Cmt` returning 1,000 to 5,000 values | `doublecap` copies past its 32-entry stack array |
| `P(2^31+1)`; `P(string of 2 GiB)` | `int` size overflow, then an out-of-bounds heap write in `newtree` (`lpeg.c:2291`) |
| a `Cmt` calling the pattern's `__gc` mid-match | use-after-free of the code array (`lpeg.c:3505`) |

**Silent corruption from network input.**
- **The defect.** `Capture.idx` is a `short` (`lpeg.c:241`). Runtime captures store
  a Lua stack index in it (`:3461`), and `Cruntime` reads it back with
  `lua_pushvalue` (`:857-858`).
- **The index wraps from the k-th live runtime capture, for k ≥ 32,764 −
  (the number of `match` arguments)**: 32,762 for `match(p, s)` and for
  `json.parse`. Orphans count (§5). A different live Lua object is then read
  from another stack slot. Measured: the aliased reads are numbers, strings,
  tables, nil and userdata, with no crash.
- **How the network reaches it.** `json.lua` decodes each `\uXXXX` escape
  through `Cmt(..., unicode16)` (`json.lua:133`). Measured on 7.94:
  - `json.parse` of a document with 33,000 escapes returns `true` with a
    string that is wrong from character 32,762 on;
  - with exactly 32,762 escapes it returns `false`.
- About 200 KB of JSON is enough, and http's default body cap is 2 MiB
  (`http.lua:163`).

**The constant table has the same defect.** `TTree.key` is `unsigned short`
(`lpeg.c:189`) and `Instruction.key` is `short` (`:307`). So constants 32,768 to
65,536 read back as nil, and from 65,537 they alias earlier ones (measured).

**Consequences:**
- no golden records a crashing or corrupted row (LESSONS #033);
- the crashes are "fix, don't reproduce" (prime directive);
- the 16-bit truncations are D4.

### 1.3 The backtrack stack is LPeg's only bound on depth, and C recursion has none

**The stack.** It holds `MAXBACK = 100` entries by default (`lpeg.c:52`), stored in
the registry (`:3336`).
- `match` starts on a 100-entry array (`:3360`, `:3488`).
- It doubles in `doublestack` (`:3403-3418`) up to the registry value, or
  raises `too many pending calls/choices`.
- No shipped file calls `setmaxstack`.

**Measured ceilings it sets on subject-driven depth:**

| input | first failure |
|---|---|
| JSON `[`×d`]`×d | 34 |
| JSON `[`×d`1]`×d, objects | 32 |
| self-recursive grammar `S <- 'a' S 'b' / ''` | 50 |
| disjoint choice `S <- '(' S ')' / 'x'`: one entry per level | 99 |
| tail call `S <- 'a' S / ''`: no stack | none: 100,000 deep matches |
| `re.compile` parentheses | 18 |

**The ceilings depend on the compiler.** With `codechoice` off, JSON fails at
21 and 16, and that build also segfaults on 12 corpus rows. So a faithful
port reproduces them only with an instruction-exact compiler (D2).

**`setmaxstack`, measured on 7.94:**
- `setmaxstack(1000)` passes depth 499 and fails at 500.
- `setmaxstack(2^31)` and `setmaxstack(5)` act as the default: narrowed into
  an `int` (`lpeg.c:3409-3410`), and floored at 100.
- `setmaxstack()` stores nil and gets the floor.
- `"1000"` is stored as a string and converted at every growth.
- `1000.5` raises `number has no integer representation`.
- The value is process-global.

**Measured on the tree oracle** (the step c and step d briefs):
- The floor is `INITBACK` (`:3360`), not `MAXBACK` (`:52`). Both are 100.
  The registry value is read only when the first 100 entries are full, so
  `setmaxstack(150)` passes depth 74 and fails at 75.
- A `setmaxstack` called from a callback changes the running match:
  `doublestack` re-reads the registry at every growth (`:3408`).
  `S <- 'a' S 'b' / ''` on a²⁰⁰b²⁰⁰ fails by default, and matches (401)
  after an in-match `setmaxstack(1000)`.

**What the stack does not bound.** These walkers recurse on the C stack with
no limit:
- `finalfix` `lpeg.c:2213`;
- `getfirst` `:1175`;
- `codegen` `:1784`, `codeand` `:1587`, `codegrammar` `:1734`;
- `pushcapture` `:831`, `tablecap` `:542`.

At nmap's 8 MB thread stack they crash at about:
- 6,159 levels of `Ct`;
- 7,699 of `P{}`;
- 45,898 of `-`, `#`, `^-1`, `Cmt` and `Cs`.

**The port's NSE thread** is spawned with no `stack_size`
(`3ba9d53fc:nmap-rs/crates/cli/src/nse.rs:73-75`, verified), which is Rust's default (2 MiB
per the std docs). A Rust stack overflow is a SIGABRT that no budget,
watchdog or `pcall` can catch, which is strictly worse than C's `C stack
overflow`. So **E2 (no recursion on the Rust stack) is a soundness
requirement**, gated by a sabotage case that reintroduces recursion (§11).

### 1.4 Calling back into Lua: six re-entry points, and no precedent for suspending mid-match

**The re-entry points:**

| what | when | where |
|---|---|---|
| `Cmt` | at match time | `runtimecap` `lpeg.c:661`, `lua_call` `:676` |
| `/f` | after the match; inside a `Cmt`, when its innermost enclosing `Cmt` closes, so after any inner `Cmt` has been called | `functioncap` `lpeg.c:610` |
| `Cf` | as `/f` | `foldcap` `lpeg.c:586` |
| `/table` | as `/f`; honours `__index` | `querycap` `lpeg.c:570-573` |
| `lpeg.locale(t)` | at the call; honours `__newindex`, in class order alnum…xdigit | `createcat` `lpeg.c:3260-3266` |
| a grammar table | at construction (`P`, an operator, or `match`'s argument 1); the initial rule is read through `__index` | `getfirstrule` `lpeg.c:2928-2933`, `lua_gettable` `:2932` |

**The corpus reaches all of the capture kinds on network data:**
- `Cmt`, with `error()` and a nested `match` inside the callback
  (`json.lua:133`, `:79-101`);
- `Cf` with `rawset`;
- `/f`;
- `/table` (`lpeg-utility.lua:141`).

**Yields.** In C, `coroutine.yield` inside any of these callbacks raises
"attempt to yield across a C-call boundary". A stackless port would allow it,
as the gsub callback already does (`pattern-gsub-callback-may-yield`). C
refuses on all six paths. Step b ledgers `lpeg-callback-may-yield` for a
grammar's `__index` and `locale(t)`'s `__newindex` (proposed: #132's fix
round adds it to DIVERGENCES.md), and step d extends it to the captures. It
is in the same family, and no golden asserts C's refusal.

**No existing `Sequence` does what LPeg needs.** The nearest is `GsubSeq`
(`3ba9d53fc:nmap-rs/crates/core/src/nse/stdlib/mod.rs:459-592`), but:
- it calls back only *between* matches (`:455`);
- its matcher state is `require_static` (`:463`, `:466`);
- it burns fuel once per replacement (`:583-588`).

LPeg must suspend **inside** a match, twice over:
- on fuel;
- at a `Cmt`, holding `Value<'gc>` dynamic captures and backtrack state
  across `SequencePoll::Call`, then resuming. Meanwhile the callback may run
  a nested `match`, raise an error object, or trigger a collection.

That is unproven in this codebase, so step 0b spikes it before anything is
scheduled on top of it (PLAYBOOK Phase 1, criterion 3).

**What is bounded and what is not:**
- **Re-entry depth** is bounded: each `SequencePoll::Call` costs one C level
  (`executor.rs:518-533`), so `Cmt`→`match` recursion stops at
  `LUAI_MAXCCALLS = 200`, as in C (194–196 levels by embedding).
- **Capture-tree size and depth within one evaluation** are not bounded by
  C levels, because they make no call. Only the Lua stack bounds them
  (`stack overflow (too many captures)`), and only if E2's cursor is truly
  iterative.

### 1.5 `nmapdb` is small, and it uncovers a shipped port bug

**The `unknown` service name.** `services.cc:228-232` stores `s_name = NULL`
for the 15,316 entries named `unknown`. So under 7.94, `port.service` and
`nmapdb.getservbyport` give nil for them.
- The port's `ServiceTable::service_name` returns `Some("unknown")`.
- Scripts see it through
  `3ba9d53fc:nmap-rs/crates/core/src/nse/nmaplib.rs:649-658,1150-1159`
  (fixed in M6.6 step a).
- Measured on 4/tcp: 7.94 sees `4=nil/nil/closed`, the port
  `4=unknown/string/closed`.
- It is the only difference between the port's table and 7.94 over all
  196,608 port/protocol pairs.
- It is now ledgered as `nmaplib-unknown-service-name`, and step a fixes
  it.

**Other findings:**
- **`core::macvendor`** agrees with 7.94 on 154,170 lookups (MA-S, then
  MA-M, then MA-L), but nothing in production calls it.
- **Its three ledgered departures from the C become visible to scripts**
  through `mac2corp`: `macvendor-parse-degrade`,
  `macvendor-empty-vendor-skipped` and `macvendor-no-fgets-truncation`.
  - **Correction.** `macvendor-empty-vendor-skipped` said a release build
    stores an empty vendor. nmap's build never defines `NDEBUG`, so the
    assert is live, and **a prefix line with no vendor aborts 7.94**
    (measured, SIGABRT at `3be01efb1:MACLookup.cc:154`, `MACLookup.cc:155` in this tree). The ledger entry is corrected.
- **No `nmap-protocols` parser** exists.
- **`getprotbynum(255)` kills 7.94** (§3).
- **`getservbyport`'s option list is unterminated** (§7).

## 2. What is ported

**`nmapdb`.** It is registered with `luaL_requiref(L,"nmapdb",…,1)`
(`nse_main.cc:565,581`), so it is a global and also in `package.loaded`.
Each function returns exactly one value, nil included, and ignores extra
arguments.

| function | C | contract (measured) | corpus |
|---|---|---|---|
| `mac2corp(s)` | `nse_db.cc:12-44` → `MACPrefix2Corp` | <ul><li>`luaL_checklstring`.</li><li>A 6-byte string is always raw bytes.</li><li>Otherwise: hex pairs, each optionally preceded by one `:`, exactly 6 bytes, the whole input used. Anything else raises `Expected a 6-byte MAC address`.</li><li>Lookup order: MA-S, MA-M, MA-L.</li></ul> | `datafiles.lua:127`; 4 callers, always 12 uppercase hex digits |
| `getservbyport(port, proto)` | `nse_db.cc:46-66` → `services.cc:315-330` | <ul><li>Checks in order: `luaL_checkinteger`, then `luaL_checkoption` over `{"tcp","udp","sctp"}` (unterminated, NUL-truncated, case-sensitive), then `Port number out of range`.</li><li>`unknown` → nil.</li></ul> | `datafiles.lua:83`; reached from unusual-port |
| `getprotbynum(n)` | `nse_db.cc:68-85` → `protocols.cc:188-196` | `n < 0` or `n > 255` → `Protocol number out of range`; 255 is drift (§3) | 0 call sites |
| `getprotbyname(s)` | `nse_db.cc:87-100` | `strcmp`: case-sensitive, NUL-truncated | 0 call sites |

**Data files:**
- **`nmap-mac-prefixes`.** Read lazily, once. A missing file prints `Cannot
  find nmap-mac-prefixes: Ethernet vendor correlation will not be performed`
  once, and every lookup is then nil. The first duplicate wins. A
  prefix-only line aborts (§1.5).
  - **C/port differences on operator-supplied data:**
    - the C ends the vendor at the first `\r` anywhere, where the port strips
      only a trailing one;
    - a NUL byte ends the vendor in C;
    - the C accepts `\v`/`\f` after the prefix.
- **`nmap-protocols`.** Parsed with `sscanf("%127s %hu")`. C already skips
  unparsable lines (`protocols.cc:121-124`); what it also does is *accept*
  `%hu`-wrapped numbers (`0x9`→0, `65542`→6, `8abc`→8). A duplicate name:
  the first wins. A missing file falls back to `/etc/protocols`, then
  `pfatal` (`:101-108`). Services resolve their protocol column through this
  file (`services.cc:194`).
- **Fallbacks.** C falls back to `/etc/services` and `/etc/protocols`. The
  port has no fallback today (`datafiles-no-etc-fallback`, now ledgered).
- **Reporting.** nmap lists lazily loaded data files in
  `printdatafilepaths` (`output.cc:2583-2659`). The port prints no "Read data
  files from" line at all.

**`lpeg`.** LPeg 0.12 (`lpeg.c:20`), an amalgamation of 11 sources from 2013.
`nse_lpeg.cc:1-21` defines six compatibility macros (`luaL_checkint`,
`lua_equal`, `lua_getfenv`, `lua_setfenv`, `lua_objlen`, `luaL_register`).
Three of them matter:
- `luaL_checkint` → `luaL_checkinteger`, assigned to an `int`;
- `lua_getfenv` → `lua_getuservalue` (the ktable is user value 1);
- `lua_equal` → `lua_compare(LUA_OPEQ)`, used at `lpeg.c:512`, `:2479`, `:2967`.
  `__eq` is unreachable there (measured), so the port may use raw equality.

**Surface (measured):**
- **22 functions:** B C Carg Cb Cc Cf Cg Cmt Cp Cs Ct P R S V locale match
  pcode ptree setmaxstack type version.
- **The `lpeg-pattern` metatable:** `__add __div __gc __index __len __mul
  __name __pow __sub __unm`, with `__index` = the `lpeg` table and no
  `__metatable`.

**Case generator** (`gen_lpeg_cases.py`). Seed 1 gives 60,945 cases:
- A constructors 462, B operators 1,664, C captures 726, D grammars 542;

**Two problems with error rows, and the fix.**
- **Position prefixes.** 15,308 of the 16,198 error rows begin `chunk:1:`,
  which is `luaL_where(L,1)`: the position of the Lua code calling into C.
  The port's stdlib errors carry no position
  (`stdlib-errors-have-no-position`).
- **Function names.** The name in `bad argument #n to 'NAME'` comes from the
  call site: `'pow'`, `'div'`, `'add'` for metamethods, `'lpeg.setmaxstack'`
  under `pcall`. The port uses fixed names (`stdlib-bad-argument-naming`).
- **Fix (E6).** The gate calls LPeg through a direct `pcall(lpeg.f, …)`, so
  neither side has a prefix. This is the M6 pattern gate's rule. Only an
  error that escapes is compared with the prefix removed. `position` and
  `argname` become named classes in the classifier and in the ledger.

**Agreement between the two oracles.** They agree on 99.96% of 60,806
cases. The 24 disagreements are tagged:

|---|---|---|
| `hashorder` | the rule name in four grammar errors (`may be left recursive`, `is not a pattern`, `empty loop in rule`, `rule '%s' undefined in given grammar`) follows table iteration order, which is salted per process | mask the name in all four, in every comparison. ## 5. What must be first-party whatever is chosen

**No crate implements LPeg.** These were checked:
- `peg` and `pest` generate parsers at compile time;
- `lua-patterns` and `lsonar` handle Lua patterns, not LPeg;
- `parsanol` is a packrat PEG with its own capture model;
- `dynparser` is GPL-3.0.

None has value-level pattern algebra, `Cmt`/`Cf`/query captures, grammars as
tables or `setmaxstack`. A crate would also sit outside the differential,
fuzz and Miri gates.

**The port therefore writes:**
- **Coercions** (`getpatt`, `lpeg.c:2390-2432`):
  - a string becomes a chain of `TChar` (`""` → true), with checked size
    arithmetic;
  - a number n: 0 → true, n > 0 → n×any, n < 0 → not(n×any);
  - a boolean, a table (grammar), a function (runtime capture), or else a
    pattern.
- **Integer arguments as the C reads them.** A number argument goes through
  `lua_tointeger` (a non-integral or out-of-range float gives 0), then is
  truncated to a 32-bit two's-complement `int`. Measured:
  - `P(2^32+2)` is `P(2)`, `P(1.5)` and `P(2^63)` are true;
  - `p^(2^32+1)` is `p^1`, and `/(2^32+1)` is `/1`;
  - `Carg(2^32+1)` is `Carg(1)`;
  - `setmaxstack(2^32+1000)` is `setmaxstack(1000)`;
  - **exceptions:** `p^1.5` raises `number has no integer representation`
    (`^` uses `luaL_checkinteger`), and `setmaxstack(1000.5)` raises the
    same.

  Reproduced (E11). Sizes derived from these values still use checked
  arithmetic.
- **`initposition`.** Negative positions count from the end, **and so do 0
  and `-0.0`** (`match(Cp(),"abc",0)` → 4). Both ends crop.
- **String captures:**
  - a trailing `%` appends a NUL byte;
  - `%N` numbers nested plain captures in pre-order (`ab|a|b|c`), and `%10`
    is `%1` followed by `0`;
  - `MAXSTRCAPS` skips extra captures silently.
- **Groups.** Group names are always strings: `Cg` and `Cb` use
  `luaL_checkstring`, so `Cg(p,1)` keys `"1"` and `Cg(p,0/0)` keys `"-nan"`.
- **Grammars.** A grammar key that converts to 1 is dropped as if it were
  the `[1]` slot.
- **Table queries.** `/{a=false}` yields `false`. A nil or NaN key yields no
  value.
- **Capture order.**
  - `/f` inside a `Cmt` runs when its innermost enclosing `Cmt` closes, so
    after any inner `Cmt`'s function; outside every `Cmt`, only on success.
  - Backtracking discards dynamic captures. `#p` does not: `IBackCommit`
    (`:3605-3611`) restores the capture list but leaves the values on the
    Lua stack as orphans (E14).
  - Evaluation is lazy, so a callback can run zero times or several:
    - a named group outside `Ct` and `Cb` is never evaluated, so its `/f`
      never runs;
    - each `Cb` evaluates its group again;
    - `/0` evaluates nothing;
    - `/"%n"` evaluates a referenced non-simple capture once per reference.
  - `/table` honours `__index`.
  - `Cf` is 0.12's fold.
- **`Cmt` results.**
  - False, nil or no value: fail.
  - True: keep the position. Values after `true`, nil included, are kept as
    captures.
  - A position read with `lua_tointeger` (`" 2 "`, `"0x3"`, `"3e0"` work):
    the new position.
  - `3.5`, 0, a table, `"x"`, `2^63` or a backward position: `invalid
    position returned by match-time capture`.
  - Only a position (or `true` alone): the `Cmt` vanishes from the capture
    list. `Cf` does not count it as a capture with no values, and an
    enclosing `/f` receives the whole match.
  - `error({})` propagates the table.
- **Captures through rule calls.** `hascaptures` does not follow a rule call
  (`numsiblings[TCall]` is 0, `lpeg.c:2139`). Three 0.12 behaviours follow,
  and are reproduced:
  - `P{"A", A=Ct(V"B"), B=C"x"}` gives `"x", {}`: a full capture placed
    after the call;
  - `P{"A", A=#V"B"*1, B=C"x"}` gives `"x"`: the and-predicate keeps the
    called rule's captures, where `#C"x"*1` gives 2;
  - `P{"A", A=C(V"B")*V"B", B=Cc(1)}` on `""` gives `1, "", 1`: the order
    is inverted.
- **Identity.** `P(p)`, `x*true`, `false*x` and `x+false` return the operand
  itself. This is visible through `rawequal`, and it fixes the tree shape the
  compiler sees.
- **Messages to reproduce exactly:**
  - `p / -1` → `bad argument #1 to 'div' (invalid number)`: the argument
    number is #1 even though the number is the second operand;
  - `stack overflow (too many captures)` at the Lua-stack ceiling,
    N_max = 999,997 − U0, where U0 is the stack in use when capture
    evaluation starts. It is 999,967 for `pcall(lpeg.match, C(1)^0, s)`
    from a standalone main chunk, 1 less per extra `match` argument, and
    about 3 less per enclosing Lua frame;
  - a bare `stack overflow`, Lua's own, when the values were pushed but the
    caller cannot take them;
  - `doublecap`'s own `too many captures`, with no prefix, at 2^26 entries,
    where the memory budget refuses first;
  - `number has no integer representation`;
  - every constructor error, verbatim.
- **`__name`.** `tostring(P(1))` is `lpeg-pattern: 0x…`, and type errors say
  `got lpeg-pattern`. The port ignores `__name` in both places:
  - for `tostring`, as recorded in `format-tostring-of-references`;
  - in the type-error helper
    (`3ba9d53fc:nmap-rs/crates/core/src/nse/stdlib/mod.rs:258-263`), which
    says `userdata` where 7.94 says `FILE*`. Now ledgered as
    `stdlib-type-errors-ignore-name`.

  E7 fixes both (done in step b).
- **`setmaxstack`** exactly as in §1.3.
- **`locale`** in the C locale. No byte ≥ 0x80 is in any class, since nmap
  never sets `LC_CTYPE`, and the class sizes are 62/52/33/10/94/26/95/32/6/26/22.
  `locale(t)` writes through `__newindex`.
- **The pattern metatable.** It must be reachable through `getmetatable`,
  its fields callable as plain functions, and `__index` must be the `lpeg`
  table.
- **The ktable and code are internal fields of the pattern object, never a
  Lua-visible table.** In C they are user value 1, which
  `debug.setuservalue` can replace: SIGSEGV on 7.94. The port exposes no
  `debug.setuservalue`, so that is unreachable, but the design must not
  depend on that.
- **For `nmapdb`:**
  - the `mac2corp` parser (spec: `model_mac.py`, which matched the C on
    300,000 fuzzed inputs);
  - an `nmap-protocols` parser;
  - `unknown` → nil;
  - a terminated option list, reusing
    `3ba9d53fc:nmap-rs/crates/core/src/nse/nmaplib.rs:452-493`'s private
    `check_option`/`c_str` (done in step a, which made them `pub(crate)`).

### D1 — Does M6.6 also take `lfs`?

**Options:**
- (a) **`nmapdb` and `lpeg` only.** `safe` and `all` keep quitting on
  `lfs`, and `vuln`, `intrusive` and `exploit` on `openssl`. The ledger entry
  names each module's milestone.
- (b) The full `lfs` (`nse_fs.cc`, 300 lines: `dir`, `link`, `mkdir`,
  `rmdir`, `get_path_separator`). `safe` then loads (334 / 0 / 18).
  - `lfs.link` would void the sandbox's premise that scripts cannot create
    links (`THREAT-MODEL.md:169`), which its TOCTOU argument rests on.
- (c) **A minimal `lfs`:** `get_path_separator`, plus `mkdir` through the
  existing write policy. No `link`, `rmdir` or `dir`. Its only corpus user,
  http-fetch, needs exactly these two (`http-fetch.nse:69,77,87`). `safe`
  then loads.

**Decided: (a) now, and (c) as a small step straight after M6.6.**
Even (b) or (c) fixes only `safe`: the other four categories wait for M6.5.
And `mkdir` is a sandbox-policy change, which deserves its own short Phase 0
rather than riding in on LPeg.

### D2 — The backtrack ceiling: exactly nmap's, or raised?

**Options:**
- (a) **Exact:** default 100, the floor of 100, `setmaxstack` with its
  narrowing, and an instruction-exact compiler, so the ceilings match (JSON
  34/32/32, grammar 50, `re` 18).
- (b) Raise it, or impose a uniform bound as M6.2 did
  (`nse-selection-depth-ceiling`), accepting deeper JSON than nmap.

**Decided: (a).** It is the corpus's only bound on subject-driven
depth, and an exact port reproduces it at no cost. The pins double as a gate
on the optimiser.

Instruction-exact holds up to the order of the non-initial grammar rules.
`collectrules` takes them in table iteration order (`lpeg.c:2965`), which C
salts per process too. So a grammar with two or more of them can be laid out
differently from run to run, with the same answers and stack use.

### D3 — LPeg's worst-case time (confirmed by step 0b)

**Options:**
- (a) **Pre-empt every stage.** Construction, the verifier, the analyses,
  codegen, the match loop and capture evaluation all burn fuel and return
  `Pending`. The pure analyses are also memoised exactly, which removes their
  exponential cost (E10).
  - Every input gets a correct LPeg's answer (nmap's, wherever nmap's is
    defined), unless the work outlasts the stall limit.
  - In that case the watchdog ends the phase and keeps the stored results
    (`lpeg-stall-limit-ends-finite-work`). C would hang or finish.
  - At load time no results exist yet: start-up fails, with rc 1.
- (b) (a) plus: after a step budget, the operation *yields its script
  thread*, so other scripts keep running and `--script-timeout` ends only
  that script. C can never produce this interleaving.
- (c) A hard per-operation step cap that raises a Lua error. This diverges on
  slow but finite work.
- (d) Pre-empt only the match loop, as C bounds nothing. Building or
  compiling a pathological grammar would then freeze the engine where the
  watchdog cannot see it.

**Decided: (a). Confirmed by step 0b (2026-10-10), with four conditions.**
- **Spike** (scratch Rust; vendored piccolo, no patch). All eight
  requirements pass natively and under Miri with no undefined behaviour:
  - Pending mid-match on fuel, with the same instruction count as an
    un-preempted run;
  - suspension at a `Cmt` holding traced dynamic values (up to 598) and a
    backtrack entry across `SequencePoll::Call`;
  - a nested match from the callback;
  - `error({})` passed through as the same object;
  - a full collection after every slice (54,003, of which 9,041 mid-match
    and 43,864 inside a `Cmt`), with the running pattern reachable only from
    the Sequence;
  - a destructive `__gc` mid-match;
  - iterative walkers and a constructor reached through `__pow` returning
    Pending, and a 1,000,000-deep tree on a 256 KiB stack;
  - one C level per `Cmt` call: `C stack overflow` at pcall depth − 2, as
    in C.

  Each requirement has a sabotage that fails it.
- **Adversarial search.** Every network-facing corpus pattern is linear in
  subject size up to 64 KiB, with growth exponents 0.98–1.01 and a flat
  envelope from 4 to 64 KiB: `json.parse`, the coap link format,
  `get_response`, `parse_fp`, ntp-info's `kvmatch`, fingerprint-strings
  (n = 4), the four http-affiliate-id `re` grammars, and `escaped_quote`.
  Measured sustained maxima in steps per byte, over subjects of at least
  1 KiB: json 22.2, `get_response` 21.5, `parse_fp` 21.0, ntp 19.6,
  `escaped_quote` 14.0, fingerprint-strings 7.7, the affiliate grammars 6–8,
  coap 6.7. That counter takes one step per VM instruction, so a span
  instruction counts once however many bytes it scans (§13).
- **Conditions:**
  1. Capture evaluation was not spiked. It counts as pre-emptible only when
     step c's cursor returns Pending on nested `Cb` back-references, and
     step d's `/f`, `Cf` and `/table` resume through `Call`. If either
     fails, D3 is re-posed for that stage alone.
  2. A match snapshots an immutable compiled program when it starts and
     never re-reads the pattern's code cache after a `Call` (E3).
  3. `getfirst` is memoised per node as A(p) ∪ (fl ∩ B(p)), not per (node,
     follow set). The latter is exponential on nullable-suffix grammars:
     2^(n+1)−1 keys. Step c gates this with a nullable-chain compile (E10).
  4. Step e's K is per pattern: 1.25 × the adversarial maximum from a
     10-minute run of `lpeg_search` (`tests/differential/m6/lpeg_search/`),
     whose selection fitness is steps / max(length, 1,024). That run counts
     the bytes each span instruction examines as steps, so K is in those
     units, re-derived from it. Twice the fixtures' figure is not a bound:
     the C itself exceeds it on 6 of 11 patterns.

(b) and (c) are not re-posed.

**History.** Decided on 2026-10-09: (a), to be confirmed after step 0b. The
spike must show that mid-match and mid-walker suspension work on piccolo,
and the adversarial search must find no super-linear corpus pattern over
network data. If either fails, (b) or a narrower (c) comes back as a
decision with the measurements attached.

### D4 — C's silent 16-bit truncations

**Options:**
- (a) reproduce them: nil, aliasing, the wrong stack slot;
- (b) **wide indices**, which give a correct LPeg's values;
- (c) raise an error at the C's threshold.

**Decided: (b), the kit's default** (the prime directive fixes defects
rather than reproducing them).
- The runtime-capture case is reachable from the network and silently
  corrupts what scripts print.
- (c) would make `json.parse` fail on large API responses.
- Every input below the thresholds is unchanged.
- Each threshold is pinned in both directions.

## 10. Engineering choices made (recorded; you may veto)

- **E1 — first-party, in `core::nse::lpeg`, against piccolo's public API.**
  - A pure part (tree, compiler, VM, capture cursor: byte-level, fuzzable,
    Miri-able) plus a thin binding, beside `net` and `nmaplib`.
  - `nmapdb` goes in `core::nse::nmapdb`, with a new `core::protocols`.
- **E2 — no recursion on the Rust stack, gated.**
  - Every walker uses an explicit stack sized through `stdlib::reserve`.
  - No new depth bound: patterns that crash C get a correct LPeg's answer,
    bounded by memory and the existing limits.
  - **Gate:** a deep-nesting test per walker, at 10× C's crash depth, plus a
    sabotage that makes one walker recursive (the test must abort).
- **E3 — re-entry by hand-written `#[derive(Collect)]` `Sequence`s**, with
  a fast path when nothing calls Lua.
  - **The rule:** snapshot an immutable compiled program at match start;
    never re-read the pattern's code cache after a `Call`.
    - Other state is re-derived at each poll from handles the `Sequence`
      owns, so no borrow outlives a poll. gc-arena already forbids storing
      a `'gc` borrow in safe Rust.
    - The hazard is semantic: re-reading the pattern's mutable cache after a
      re-entry is the port's form of C's use-after-free
      (`lpeg-code-freed-during-match`, proposed).
  - `async_sequence` is not used, because its futures cannot hold `'gc`
    values.
  - Step 0b's spike validated the design. Its `RefetchCode` sabotage, which
    re-reads the code after a `Call`, is caught.
- **E4 — memory.** Every buffer grows through `stdlib::reserve`. A refusal
  gives `not enough memory`.
- **E5 — `ptree` and `pcode`** check their arguments (and `ptree` builds the
  grammar), then raise `function only implemented in debug mode`, as 7.94
  does. Dropping the printer is faithful, not a divergence.
- **E6 — error text.**
  - Byte-exact for LPeg's own messages.
  - The gate calls through a direct `pcall`.
  - `position` and `argname` are named classes, under the existing
    `stdlib-errors-have-no-position` and `stdlib-bad-argument-naming`.
  - LPeg's errors can carry `luaL_where` positions, byte-exactly. The port
    has `where_at(1)` and `function_name`
    (`004285841:nmap-rs/crates/core/src/nse/nmapdb.rs:359-369`), and step
    b's constructors already use them
    (`3ed2aedf5:nmap-rs/crates/core/src/nse/lpeg/mod.rs:1308-1319`, with
    `lpeg-bad-argument-naming`). So the `position` class can shrink to what
    is not LPeg's.
  - Four rule-name messages are masked.
- **E7 — honour `__name`** in `tostring` and in the type-error helper, as
  `luaL_tolstring` and `luaL_typeerror` do: the raw `__name` of any value's
  metatable (the string metatable included, for type errors), cut at its
  first NUL, as bytes. This updates `format-tostring-of-references` and
  closes `stdlib-type-errors-ignore-name`. VM-raised errors still print the
  whole name.
- **E8 — `nmapdb` registration and loaders.**
  - Registered at step a, global and in `package.loaded`. No harmful
    half-state, measured on 7.94 with only `nmapdb` present (0 mismatches
    over 611 scripts).
  - Data files load lazily, as bytes, with the C's full one-time messages.
    Loaders record what they read, for a later "Read data files from" line.
  - `core::protocols` rejects the `%hu`-wrapped numbers that C misreads, and
    skips bad lines as C already does.
  - No `/etc` fallback.
  - `unknown` → nil in `nmapdb` and in `port.service`. Normal and XML output
    still print `unknown`, `name_confidence` stays 3, and the detection type
    stays `table`. The entries stay in the table for `-p unknown`.
  - `core::macvendor`'s three ledgered departures are kept and now reach
    scripts. Their entries are updated to say so at step a.
  - `core::macvendor` moves from `&str` to bytes
    (`3ba9d53fc:nmap-rs/crates/core/src/macvendor.rs:76`; done in step a), and
    its `\r`, NUL and `\v`/`\f` handling is aligned with the C.
- **E9 — `lpeg` is registered only when every capture kind works (step e).**
  Registering earlier would let scripts load and then fail at run time in
  `json.parse`.
- **E10 — exact memoisation of the pure analyses.**
  - **`getfirst`** is memoised per node, in the closed form
    FIRST(p, fl) = A(p) ∪ (fl ∩ B(p)). A(p), B(p) and the empty/run-time
    flag do not depend on the follow set fl.
    - Each case at `lpeg.c:1175-1250` admits it. A patched tree oracle
      checked it against the C at 111,616 or more codegen call sites, with
      0 mismatches (step c's brief).
    - A memo per (node, follow set) is not enough. On the nullable-suffix
      chain `Rᵢ ← Rᵢ₋₁ cᵢ^-1 / Rᵢ₋₁ dᵢ^-1` it holds 2^(n+1)−1 keys, and C
      compiles that grammar exponentially: 0.004 / 0.015 / 0.062 s at
      n = 14 / 16 / 18. Step c gates it with a nullable-chain compile.
  - **`getfirst` re-entry.** The walk detects a call target already on its
    current walk, and raises at the first match. This is exact, because C's
    descent does not depend on the follow set. It replaces the verifier's
    refusal of left calls through `lpeg.B` (§7,
    `lpeg-getfirst-unbounded-recursion`).
  - **`headfail`** and **`nullable`/`nofail`** carry no other state, so
    they are memoised per node.
  - **`fixedlen`** carries the call count (`:1137`), so its memo key is
    (node, count). Memoised lengths can pass `i64` (doubling grammars reach
    2^200 in linear time), so they saturate. That is in codegen only, where
    every consumer is a threshold test. `lpeg.B` needs exact lengths, so it
    stays exact, unmemoised and fuel-checked.
  - The verifier keeps its left-recursion path and burns fuel instead.
- **E11 — 32-bit narrowing of integer arguments is reproduced.** It is
  deterministic and crash-free, and an operator can observe it through
  `fingerprint-strings.n`. Sizes derived from it are checked.
- **E12 — M6.2's and M6.3's Rust grammars stay as they are.**
- **E13 — compile lazily and cache on the pattern**, as `lp_match` does
  (`lpeg.c:3206`). The laziness is observable: the cost lands on the first match.
  Step c's exponential-compile test relies on it.
  - The program is attached only when compilation succeeds. C attaches it
    first (`:1869`), so a `not enough memory` part-way through codegen
    would leave an incomplete program that the next match runs (§13).
- **E14 — `#p` keeps a `Cmt`'s values as orphans, as C does.**
  - `IBackCommit` (`:3605-3611`) restores the capture list but not the Lua
    stack. So the values a `Cmt` returned inside `#p` stay live until a
    failure below them.
  - A `(#Cmt)^0` loop that returns a value overflows the stack after about
    999,957 iterations, with a bare `stack overflow`. Returning only `true`,
    it succeeds.
  - Reproduced: it is deterministic and crash-free, and no corpus pattern
    has `#Cmt`. Ledgered at step d as
    `lpeg-and-predicate-keeps-dynamic-captures` (proposed). Reproducing the
    overflow needs live dynamic values charged against the Lua stack, the
    first option of step d's S08 gate.

## 12. Exit criterion

**The scenarios run on the real datadir:**

```
nmap-rs --datadir <repo> -Pn -n -p 1 -sC 127.0.0.1
```

They also run with `-A`, `--script default` and `--script version`.

**What the parser asserts.** It reads the `-d2` lines that both programs
print (`NSE: Script X was selected by …`, `NSE: Loaded '…'`, `NSE: Failed to
load '…'`). The last is the quiet line (`nse_main.lua:632`), printed at `-v`
or any `-d`.
- 127 `selected` lines for `default`, which guards against the fixture-datadir
  blind spot;
- the port's `Loaded` lines are 7.94's minus a pinned list of the 6 scripts
  that need `openssl`;
- its `Failed to load` lines are exactly that list;
- the same for `--script version` (48 selected, 48 loaded, none failed);
- for `-A`, the `default` lists again, and none of the 31 `version`-only
  scripts;
- no `QUITTING`, and rc 0.

**The `-A` row needs its own oracle and a tolerance.**
- 7.94's `-A` selects 158 scripts: `default` and `version`, 17 of them in
  both. `-A` implies `-sV`, which adds the `version` rule (`nmap.cc:2084-2085`,
  `nse_main.lua:708`).
- The port's `-sV` runs no scripts yet, so its `-A` selects `default` only.
  The 31 `version`-only names are a harness tolerance, written into
  `nse-sv-version-scripts-pending`. When it closes, the row compares all 158.
- 7.94 cannot run `-A` (or `-O`) with `--datadir <repo>`. The repo's
  `nmap-os-db` is for 7.94.2 and later (`nmap-os-db:23`), and 7.94 aborts on
  an assertion (`3be01efb1:osscan.cc:681`, rc 134). So the oracle is 7.94's
  `-sC -sV`, which selects the same 158 in the same order.

**The pinned list is a harness tolerance.** It gets its own ledger entry,
`nse-sc-openssl-quiet-drops`, with an M6.5 expiry (LESSONS #031).

**One executed script per module, since `-p 1 -sC` runs almost nothing:**
- **`nmapdb`:** address-info on an IPv6 EUI-64 address, with the same
  command on both binaries (verified):
  ```
  -6 -Pn -n -sT -p 1 --exclude-ports 1 --script address-info 2001:db8::211:22ff:fe33:4455
  ```
  The port list is empty, so nothing is scanned, and the host script still
  runs. Both print `MAC address: 00:11:22:33:44:55` and `manuf: Cimsys`, with
  identical script rows, and nothing is sent (strace).
- **`lpeg`:** riak-http-info on 8098, against a loopback listener serving
  `\u` escapes.
  - Its output has a fixed key order.
  - Its JSON nesting ceiling for this document's shape is 29 / 30: 7.94
    passes at 29 and fails at 30 with `too many pending calls/choices`. That
    pins D2 end to end.
  - couchdb-stats is not used: its output order is table iteration order.

**What it retires:**
- `nse-sc-aborts-on-unported-modules`, replaced by
  `nse-categories-abort-on-unported-modules` (proposed) for `safe` and `all`
  (`lfs`) and for `vuln`, `intrusive` and `exploit` (`openssl`), each with
  its expiry. `all` needs both;
- the `lpeg`/`re`/`nmapdb` half of `nse-c-modules-pending`.

## 13. Not verified

- **Adversarial time beyond what step 0b measured.**
  - Subjects above 64 KiB are extrapolated (an http body can reach 2 MiB).
  - fingerprint-strings was searched only at n = 4.
  - The original search ran 120 s per pattern, not 10 minutes. A corrected
    300 s re-run covered 9 patterns, but no pattern has had the 10-minute
    budget.
  - **The step counter's blind spot.** It adds one per VM instruction, and
    `ISpan` (`S(...)^0`, `(P(1) - x)^0`) scans a whole run of bytes as one
    instruction. So a quadratic pattern can look linear:
    `anywhere(P"a"^0 * "b")` on runs of `a` stays at a flat 6.00 steps per
    byte from 1,000 to 8,000 bytes, while its CPU time grows about 30-fold.
    By inspection none of the 11 network-facing patterns has that shape:
    their retry loops start with a literal or bounded head. That was not
    measured, and the sustained maxima in D3 were measured with this
    counter. Step e's search counts the bytes each span instruction examines
    (§11).
- **Capture evaluation's pre-emption**, including the resumable `/f`, `Cf`
  and `/table` cursor: not spiked (steps c and d).
- **Why 7.94's LPeg re-entry costs one C level more than its `gsub`.** It is
  not the Lua version: the standalone oracle gives 0 under 5.4.4, 5.4.6 and
  5.4.8. Nor why 7.94's probe has 11 more free stack slots for captures; that
  fewer frames lie below its call is inferred.
- **Memory of the per-node `getfirst` memo, and the port's dynamic-capture
  ceiling** (decided at step d), are unmeasured.
- **Whether `json.parse` reaches `doublecap`'s over-read**, which needs only
  one value per call: not run under ASan.
- **CI on GitHub.** It has not run since 5 October, so
  `regen_m66_lpeg.sh --check` and `--check-794` (against Ubuntu's nmap
  package) have run only locally.
- **Spike scope.** The toy is not instruction-exact (its ceiling is one below
  C's). Miri ran at reduced sizes, across four runs.
- **C behaviour established by reading only**, beyond what the oracle can
  reach:
  - an incomplete program cached after `not enough memory` part-way through
    codegen, because `compile` assigns `p->code` before generating
    (`lpeg.c:1869`). The port attaches a program only on success (E13);
  - `doublecap`'s `too many captures` at 2^26 entries (`:3392`), a 1 GiB
    capture list: the memory budget refuses first;
  - a fixed length above 2^31 (undefined in C).
- **Whether every quarantined peephole row's answer is reachable at step c.**
  Many use `/f` or `Cmt`.
- **The `fingerprint-strings.n` narrowing and overflow end to end.** They
  were shown on direct LPeg calls only.
- **Whether the runtime-capture wrap can ever read outside `L->stack`.** It
  reads live objects from adjacent slots, which is consistent with staying
  inside.
- **The NSE thread's stack size** (2 MiB per the std docs). E2 makes it moot.
- **Run-time behaviour of the scripts `nmapdb` alone unblocks.** Their
  loading was measured on 7.94.
- **piccolo's table iteration order.** It affects the masked rule names, and,
  as in C, the code layout of a grammar with two or more non-initial rules,
  but not its answers or stack use (D2).
- **`lpeg.c:2697-3180` and `:3500-3626`.** These were read only at the sites
  cited.
- **Port-side throughput** of the 61k-case corpus.
- **Windows behaviour** of the data-file loaders.
- **The size estimate in §0.**
