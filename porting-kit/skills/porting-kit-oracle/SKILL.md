# Porting Kit — establish the oracle (test harness first)

Wraps the differential + golden harnesses, PLAYBOOK Phase 2 and
`porting-kit/ORACLE-CHECKS.md` (the procedure behind steps 2, 5d–5f and 6a).
**Do this before writing Rust.** TRACTOR's central finding: most failures are at the
semantic-comparison stage, not build time — "it builds" tells you almost nothing.

## Procedure
1. **Lock the C binary** at a known commit as the reference oracle.
2. **Build the input matrix** from `porting-kit/harnesses/differential/input-matrix.example.toml`.
   Cover every output format, every flag, empty/edge/large inputs, malformed/hostile
   inputs and **every integer boundary**. **Defaults are inputs:** each option also gets a
   row where it is omitted, plus the combinations users run (LESSONS #047).
3. **Capture + version the golden corpus**, flagging oracle nondeterminism:
   `python3 porting-kit/harnesses/golden/golden.py capture --oracle <c-bin> --matrix <m> --corpus <dir>`
   A golden encodes the host that generated it — print only facts true on every host
   (LESSONS #034). Harden the harness for its host (LESSONS #001).
4. **Tune normalization** (`porting-kit/harnesses/differential/normalize.py`): mask noise
   identically on both sides. A rule that hides a *ledgered* difference is a
   **tolerance**: scope it to its case ids in a `[[tolerance]]` file and let
   `diff_run.py --tolerances` pin its membership (LESSONS #048).
5. **Validate every vector against the C first**, and **hold back a hidden acceptance set**.
5a. **An oracle copies the C; it never restates it** — paste and diff; name substituted
   inputs (LESSONS #019).
5b. **Sanitize the pasted C over truncated input** (`-fsanitize=address -g -O0`), and build
   it in the embedded library's own checking mode too (`LUA_USE_APICHECK`) (LESSONS #020, #051).
5c. **Record no golden where the C is undefined**; cover that region from the Rust side.
   When a C flaw is found later, sweep the corpora for inputs that reach it (LESSONS #033).
5d. **UB-screen every golden generated by running C** under
   `-fsanitize=address,undefined -fno-sanitize-recover=all` plus the runtime's API checks;
   commit the screen's record with a digest of the corpus, the C sources and the flags, and
   make the generator refuse a mismatch. UB that looks deterministic is still UB; keep
   goldens greppable or decode them before any sweep (LESSONS #049).
5e. **Reach census:** rows per exposed function; zero rows = unverified. A dependency's own
   compatibility list is not an oracle (LESSONS #043).
5f. **Sabotage the C to measure the corpus:** each variant breaks one behaviour; the corpus
   must catch every one (LESSONS #044).
6. **Seed `DIVERGENCES.md`** (copy `porting-kit/skeleton/DIVERGENCES.md`) from the
   Phase-0 flaw scan.
6a. **Declare the resource bound per untrusted input** in the threat model; the module loop
   scales the port against this oracle (`porting-kit/RESOURCE-BOUNDS.md`).
7. **Wire the differential** (used per module in `porting-kit-module`):
   `python3 porting-kit/harnesses/differential/diff_run.py --oracle <c> --rust <rust> --matrix <m> --ledger DIVERGENCES.md`
   The verdict is stdout **and** exit code; a per-case timeout is the liveness backstop.
   For a C-ABI **library**, use a `cando`-style function-level harness (synthesis Step 0.5).

## Integrity
Harness paths/subcommands/flags must match the kit; `check_skills.py` also fails if a
lesson that amended Phase 2 is not cited here (LESSONS #046). If they drift, fix the
reference and re-run `make -C porting-kit check-kit`.
